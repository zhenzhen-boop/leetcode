# Rust：Merge Two Sorted Lists 学習メモ

## 1\. `pub` とアクセス制御

Rustでは、`pub` をつけることで、項目を外部からアクセス可能にできる。

```
pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}
```

- `pub struct ListNode`：構造体を外部から利用可能にする。
- `pub val`：フィールド `val` を公開する。
- `pub next`：フィールド `next` を公開する。
- `pub` をつけていないフィールドは非公開になる。

**注意：** 非公開の項目にアクセスできる範囲は、単純に「同じファイル内」ではなく、Rustのモジュール構造によって決まる。

## 2\. `Option<T>` とは

`Option<T>` は、値が存在する場合と存在しない場合を表す型。

- `Some(value)`：値が存在する。
- `None`：値が存在しない。

連結リストの末尾は次のノードが存在しないため、`None` で表せる。

```
let x: Option<i32> = Some(10);
let y: Option<i32> = None;
```

今回のコードでは、次のように使う。

```
next: Option<Box<ListNode>>
```

これは、次のノードが存在すれば `Some(Box<ListNode>)`、存在しなければ `None` になるという意味。

## 3\. `Box<T>` とは

`Box<T>` は、ヒープ上に確保された値を所有するスマートポインタ。

```
next: Option<Box<ListNode>>
```

`Box<ListNode>` を使う主な理由は、連結リストのような再帰的なデータ構造を定義するため。

もし次のように定義すると、

```
struct ListNode {
    val: i32,
    next: Option<ListNode>,
}
```

`ListNode` の中に `ListNode` が直接含まれるため、型のサイズを有限に決められない。

一方、`Box<ListNode>` はポインタとして一定のサイズを持つため、再帰的な構造を定義できる。

## 4\. `ListNode` の定義と `Self`

```
#[derive(PartialEq, Eq, Clone, Debug)]
pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}

impl ListNode {
    #[inline]
    fn new(val: i32) -> Self {
        ListNode {
            val,
            next: None,
        }
    }
}
```

- `#[derive(...)]`：指定したトレイトの実装を自動生成する。
- `impl ListNode`：`ListNode` に関連関数やメソッドを実装する。
- `Self`：実装対象の型である `ListNode` を表す。
- `ListNode::new(0)`：値が `0` で、次のノードを持たないノードを生成する。
- `#[inline]`：コンパイラにインライン化を促すヒント。必ずインライン化されるわけではない。

## 5\. 所有権と `Option` の操作

### `unwrap()`

`Option<T>` から中身の `T` を取り出す。

```
let x: Option<i32> = Some(10);
let y: i32 = x.unwrap();
```

`None` に対して `unwrap()` を使うと、実行時にパニックする。

### `take()`

値を取り出し、元の場所を `None` にする。

```
let mut x: Option<i32> = Some(10);
let y = x.take();

// y = Some(10)
// x = None
```

`take()` は、値を取り出す対象を変更できる必要がある。

### `as_ref()`

中身を不変参照で借りる。

```
ptr1.as_ref().unwrap().val
```

`ptr1` 自体の所有権を移動せずに、ノードの `val` を参照できる。

値を比較したいときに便利。

### `as_mut()`

中身を可変参照で借りる。

```
tail.next.as_mut().unwrap()
```

所有権を移動せずに、ノードを可変参照で操作できる。

### 4つの使い分け

| メソッド | 役割 |
| --- | --- |
| `unwrap()` | `Option<T>` から `T` を取り出す |
| `take()` | 値を取り出し、元の場所を `None` にする |
| `as_ref()` | 中身を不変参照で借りる |
| `as_mut()` | 中身を可変参照で借りる |

**重要：** `unwrap()` は所有権を移動するためだけのメソッドではない。実際に所有権が移動するかどうかは、取り出す値が所有値なのか参照なのかによって決まる。

## 6\. `dummy` と `tail` の役割

```
let mut dummy = ListNode::new(0);
let mut tail = &mut dummy;
```

### `dummy`

結合後のリストの先頭を管理するためのダミーノード。

最初の実データを持つノードを特別扱いせずに、同じ方法でノードをつなげられる。

最後に `dummy.next` を返せば、ダミーノードを結果に含めずに済む。

### `tail`

現在の結合リストの末尾を指す可変参照。

```
tail.next = Some(node);
tail = tail.next.as_mut().unwrap();
```

- `tail.next = Some(node)`：新しいノードを末尾につなぐ。
- `tail = tail.next.as_mut().unwrap()`：`tail` を新しい末尾へ進める。

`tail` 自体は `ListNode` ではなく、`&mut ListNode` という可変参照。

そのため、`tail` に `Box<ListNode>` を直接代入することはできない。

## 7\. `take()` を使って連結リストを進める

例えば、次のリストがあるとする。

```
ptr1
 ↓
[1] → [3] → [5] → None
```

先頭の `[1]` だけを結合先に移し、残りの `[3] → [5]` は `ptr1` に残したい。

そのために、一時変数 `node` を使う。

```
let mut node = ptr1.take().unwrap();
ptr1 = node.next.take();
tail.next = Some(node);
tail = tail.next.as_mut().unwrap();
```

### STEP 1：先頭ノードを取り出す

```
let mut node = ptr1.take().unwrap();
```

`ptr1` の所有権を移し、`node` に先頭ノードを保持する。

この時点では、`node` は残りのリストも所有している。

### STEP 2：残りのリストを切り離す

```
ptr1 = node.next.take();
```

`node.next` から残りのリストを取り出して `ptr1` に移す。

これにより、`node.next` は `None` になる。

```
node             ptr1
 ↓                ↓
[1] → None       [3] → [5] → None
```

### STEP 3：先頭ノードだけをつなぐ

```
tail.next = Some(node);
```

`node` が所有する先頭ノードを、結合リストの末尾につなぐ。

### STEP 4：末尾を進める

```
tail = tail.next.as_mut().unwrap();
```

新しくつないだノードへの可変参照を取得し、`tail` を進める。

## 8\. なぜ `node` という一時変数が必要なのか？

次のコードでは、

```
tail.next = ptr1.take();
```

`ptr1` が持っているリスト全体が `tail.next` に移動する。

しかし、マージ処理では先頭ノードだけを取り出して、残りのリストは次の比較に使いたい。

そのため、

1. `ptr1` から先頭ノードを取り出す。
2. `node.next.take()` で残りのリストを切り離す。
3. 先頭ノードだけを `tail.next` に接続する。

という手順を踏む。

**`node`****を作る目的は、結合先に移すノードと、次の処理に回すリストを分離して管理すること。**

## 9\. `merge_two_lists` の実装

```
impl Solution {
    pub fn merge_two_lists(
        list1: Option<Box<ListNode>>,
        list2: Option<Box<ListNode>>,
    ) -> Option<Box<ListNode>> {
        let mut ptr1 = list1;
        let mut ptr2 = list2;

        let mut dummy = ListNode::new(0);
        let mut tail = &mut dummy;

        while ptr1.is_some() && ptr2.is_some() {
            if ptr1.as_ref().unwrap().val <= ptr2.as_ref().unwrap().val {
                let mut node = ptr1.take().unwrap();
                ptr1 = node.next.take();
                tail.next = Some(node);
            } else {
                let mut node = ptr2.take().unwrap();
                ptr2 = node.next.take();
                tail.next = Some(node);
            }

            tail = tail.next.as_mut().unwrap();
        }

        // 残ったリストをそのまま接続する
        tail.next = if ptr1.is_some() {
            ptr1
        } else {
            ptr2
        };

        dummy.next
    }
}
```

### 処理の流れ

1. `ptr1` と `ptr2` が両方存在する間、先頭の値を比較する。
2. 小さい方の先頭ノードを `node` に取り出す。
3. `node.next.take()` で残りのリストを元のポインタに戻す。
4. `node` を `tail.next` に接続する。
5. `tail` を新しい末尾に進める。
6. 片方が空になったら、残ったリストをそのまま接続する。
7. `dummy.next` を返す。

## 10\. 学習時に意識すること

連結リストの所有権を操作するときは、次の3点を考える。

1. **何を移動したいか？**
   - 今回は先頭ノード1個。
2. **何を残したいか？**
   - 残りのリスト。
3. **次のノードへのつながりを確保したか？**
   - `node.next.take()` で残りのリストを確保する。

Rustでは、ノードを移動すると元の場所の値がなくなることがある。そのため、次に必要なノードへのつながりを確保してから、結合先へ移動することが重要。

**基本方針：比較には参照を使い、ノードの移動には****`take()`****を使い、末尾の操作には可変参照を使う。**
